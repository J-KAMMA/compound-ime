# 判定の門（生成が要るかを決める小さな模型）の準備

2026-10-19〜20、枝 `exp/jev-gate`（`exp/jev-design` の続き）。今回は材料づくり・学習の台本・机上の評価の仕組みまで。
本番の学習は Google Colab の L4 で別に行う。IME への組み込みはしていない。

## 役割

`docs/jev-design.md` の 4 の案。生成なしの候補（人工知能なしの出力、辞書の文全体、Mozc の組）から、
小さな模型が「生成（all_zenzai）が要るか」を決める。要らないと決めた変換は、生成なしの候補の中から選んだ答えをそのまま返す。
机上の見込み（zenz を門にした場合）は、1字あたりの点が -0.1 未満の文だけ生成に戻すと正解 4,823（本線 4,858 の 35 文少ない）、
生成に回るのは 15.8%。`gate_eval.py` はこの値を再現する（下の 5）。門に zenz を使うと門だけで生成と同じくらい時間がかかるので、小さな模型で置き換える。

## 1. 材料

`.github/workflows/jev-gate-data.yml`（`linux-test.yml` から exp/jev-gate の枝のときだけ呼ばれる。手動なら `gate_count`、`gate_shards` を決める）。

1. `tools/jev_gate_sentences.py`: 試験に使っていないウィキペディアの分割（train-00011、SHA256 固定）から、段落ごとに1文
   （10〜40字、漢字・かな・ー・、。だけ）。SudachiPy の読みからローマ字を作る。試験の文（`tests/conversion`）と表記・読みが同じか
   含む文は除く（`bd.TestExclusion`）。1つ前の文（同じ段落、80字まで）を 60% の文に前の文として付ける。ローマ字が同じ文は1つだけ。
2. 組ごと（1組 約2,000文）に別の計算機で:
   人工知能なしの候補の書き出し（`tools/jev_collect.sh gate`、文節ごとの上位16、Mozc の組、辞書の文全体）→
   v5（生成あり）の出力（`tools/context_convert.sh`、本線と同じ設定、前の文は文ごとに渡す）→
   `tools/jev_score.cpp` で今の zenz v5 が候補すべて（平均36個）に点を付ける → 記録（`tools/jev_gate_build.py`）。
   v5 の出力が人工知能なしの出力と 15% 未満しか違わなければ、人工知能が効いていないとみなして失敗にする
   （最初の試行で、ライブラリの場所を渡し忘れて人工知能が動かなかったのを、この検査の元になる統計で見つけて直した）。
3. まとめ（`jevgate-material`）: `train-records.jsonl.gz`（組の記録をつないだもの）と `stats.txt`。
   `jevgate-records-<組>` は組ごとの記録、`jevgate-test-records` は試験の組の記録（下の 5）。リポジトリには入れない。

記録の書式と、ラベル `need`（生成なしの候補の zenz 最大 ≠ v5 の出力）、`need_top1`（人工知能なしの出力 ≠ v5 の出力）、
`sel_ok`、`v5_ok`、候補ごとの zenz の点（蒸留の教師）は `tools/jev_gate_build.py` の冒頭に書いてある。

### 小さな規模（4,000 文、2組）の結果（run 39285081642）

- 記録 4,000（前の文つき 1,509）。生成が要る 23.6%、要らない 76.4%。人工知能なしの出力 ≠ v5 は 51.0%。
- 正解率: v5 65.3%、zenz 最大 62.3%、人工知能なし 42.9%。v5 だけが正解（生成を省くと損）6.4%。
- 1組（2,000文）の時間は約28〜36分（候補の書き出し、v5、zenz の採点を含む）。

### 本番の材料（run 39292104219、100,000 文、50組）

- 成果物 `jevgate-material`（`train-records.jsonl.gz` 約45MB、`stats.txt`）、`jevgate-records-1`〜`50`、`jevgate-test-records`（保存60日）。全組成功、約5時間半。
- 記録 99,999（前の文つき 37,854）。**生成が要る 24.3%（24,304）／要らない 75.7%（75,695）**（要る＝生成なしの候補の zenz 最大が v5 の出力と違う）。
- 人工知能なしの出力 ≠ v5 の出力 49.5%。正解率: v5 65.1%、zenz 最大 61.4%、人工知能なし 43.0%。v5 だけが正解 6.8%。
- 小さな規模の確認（CPU、この材料の先頭2万文、d=128・2層・k=4、4周、約5分）: 確かめ用の AUC は need 0.75、need_k 0.70。試験の組で生成 62.7% に回してようやく 4,444 正解
  （v5 -414、zenz の門は 15.8% で -35）。小さすぎる模型・少ない学習なので、見込みではなく流れの確認。本番（d=256・全部の記録・8周）で zenz の門にどこまで近づくかが次の問い。

## 2. 模型（`tools/jev-gate/jevgate.py`）

文字単位の符号化器（前置きの正規化 pre-LN、GELU）。既定は d=256・4層・4頭・ffn 1024・語彙4,096字で約450万の数。

- 入力の並び: `[先頭] 前の文の終わり24字 [区切り] 読み（ひらがな、64字まで）[区切り]` のあとに、生成なしの候補を k 個
  （人工知能なしの出力、辞書の文全体、Mozc の組の順。各候補40字まで＋終わりの印）。
  文字の番号、種類（前置き／前の文／読み／候補）、位置（前置きと候補で別の表）、候補の順位、候補の出どころ（n/w/c）の埋め込みを足す。
- 注意の形（Jev と同じ、候補どうしは見えない）: 前置きは前置きだけを見て、各候補は前置きと自分だけを見る。
- 出力: 門 4つの確率 `need`（全部の候補から決めた教師）、`need_k`（入力の上位 k 個だけで決めた教師。IME で使うのはこれ）、
  `need_top1`、`harm_k`（v5 は正解で生成なしの選択は不正解）。候補ごとの点（zenz の点の蒸留。最大との差÷10 を -3〜0 に切ったものの回帰＋
  最大の候補の順位の交差エントロピー）。生成なしの答えは、模型の点が最大の候補。門は 先頭の状態・最良の候補・先頭の候補の平均と、点・差・長さから出す。
- 学習: AdamW、bf16（GPU）、周ごとに確かめ用（id の指紋で2%）の AUC と「しきい値ごとの生成の割合・正解数」を表示、
  10分ごとにチェックポイント（最新の2つ）、再開は同じ出力フォルダで同じ命令。束ねる仕事は先読みの流れで行う。
- 小さな規模の確認（CPU、4,000 文、d=128・2層、8周）は 約3分で完走（確かめ用 79 文では当然まだ弱い）。

Colab: `tools/jev-gate/train.ipynb`（⑨の作りに合わせた手順書。①設定→②GPU とドライブ→③台本→④確認→⑤材料→⑥件数→⑦学習→⑧確かめ→⑨試験の組の評価→⑩書き出し）。
結果は `マイドライブ/jev-gate/<RUN_NAME>/`（`run/` に途中と最終、`result/` に評価・重みの表）。材料の取り方は自動（GH_TOKEN のシークレットと run の番号）か、
成果物の zip を展開してドライブに置く。時間の見積り: 30万文・k=4・8周で L4 1〜2時間（実際の速さは⑦が出し直す。未測定）。

## 3. 推論の形と時間（目標 5ms 以下）

選んだ形: **C++ だけで書いた推論（重みの表を読む）**。`tools/jev-gate/jevgate_infer.cpp`（約600行、外部の部品なし、AVX2＋OpenMP）。
`jevgate.py export` が書く重みの表（JEVG。単精度は約18MB、半精度は約9MB。語彙は別の json）を読む。
torch の出力と最大 5e-7 の差（半精度の重みで 3e-4）で一致することを `check` で確かめられる。

理由: ① 注意の形（候補どうしを見えなくする）をそのまま書ける。② IME に足す部品がない（ONNX Runtime は DLL が約十数MB増える）。
③ 速さは ONNX Runtime と同じ（同じ形で 1スレッド 24.8ms、4スレッド 12.8ms。自作 25.2ms、12.4ms）。
llama.cpp の GGUF は、BERT の形では候補どうしを見えなくする注意と、候補ごとの点の頭を持てないため見送った（枝の配列で表せるが未検証）。
ONNX は予備（`torch.onnx.export` で書き出せるのは確認した）。

1回の時間（ミリ秒、前置き60字、候補は1個25字、乱数の重みで同じ形。`jev-gate-bench.yml`、run 39275619954。
GitHub は AMD EPYC 9V74 の4つ。手元は Ryzen 7 8840U、ほかの処理がある中での測定で上下する）:

見方: 時間はほぼ語片の数（前置き＋候補×長さ）に比例する。**5ms 以下に収まるのは、450万の形なら候補なし（読みと前の文だけ、4スレッド）、
候補を入れるなら d=192・3層で k≤2（4スレッド）、d=128 で k≤4**。450万・k=4 は 4スレッドで約12ms。
さらに縮める手: 8ビット整数化（約2倍の見込み、未実装）、前の文を 12字に、候補を上位の差分だけにする。
手元の PC（Ryzen 7 8840U）では、450万・候補なしが約5ms（4スレッド）、1スレッドなら約9ms。

## 4. 机上の評価（`tools/jev-gate/gate_eval.py`）

```
python tools/jev_gate_build.py test <jev-* の材料> tests/conversion <linux-results> <jev-score-*> test-records.jsonl.gz   # CI が jevgate-test-records として作る
python tools/jev-gate/jevgate.py predict --ckpt final.pt --records test-records.jsonl.gz --out pred.tsv
python tools/jev-gate/gate_eval.py test-records.jsonl.gz --pred pred.tsv --head need_k --select student --gate-ms 6 --cand-ms 10 --by-set
```

出力: ① 生成に回す割合を決めたときの正解数（答えを知っている門・zenz の1字あたりの点・模型）、
② zenz の門の再現（-0.1 で 4,823 正解・15.8%、-0.05 で 4,829・22.1%。docs/jev-design.md の値と一致）、
③ 模型のしきい値ごとの正解数・v5 との差・生成の割合・速さの見込み、④ 試験ごとの内訳。
生成なしの答えの選び方は `student`（模型の点の最大。IME で使える形）、`zenz`（zenz の点の最大。上限）、`top1`（人工知能なしの出力）。
速さの見込み = 門 + 候補作り + 生成に回る割合 × 生成の平均時間（GitHub 3スレッドの測定値、ja400 85.5・前の文なし 253.5・前の文あり 334.6・ほか 234.8）。
門と候補作りの時間は仮の値（既定 6、10）。**しきい値は学習時の確かめ用で決める**（試験の文で決めると良く見える）。

小さな規模（4,000 文、d=128・2層、3分）の模型でも全部の流れが動いた（正解は v5 より大きく下がる。規模が足りないため）。
流れの確認が目的で、品質の見込みではない。

## 5. 注意・次の一歩

- 本番の学習（Colab）の後、学習時の確かめ用で k と形（d=256・4層か、d=192・3層で k=2 か）を決める。
- 時間の測定は乱数の重みでの形の測定。IME に組み込むときの前処理（候補作り、文字の番号付け）の時間は含まない。
- 手元の時間は1回の測定で、PC のほかの処理の影響を受ける。
- 材料と重みはリポジトリに入れない（成果物とドライブに置く）。試験の文は学習に使っていない。
