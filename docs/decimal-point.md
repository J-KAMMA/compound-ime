# 数字の間の「.」「,」を小数点・桁区切りにする（2026-10-21）

利用者の報告: 「4.1」と打つと「4。1」になる（数字の間の点が句点になる）。

## 原因（調べた順と根拠）

調べた土台は Mozc 2d993fd（BUILD.md の固定版）。手元で動く変換エンジン（Linux 版、人工知能なし）に、数字を半角にする設定ファイル（`character_form_rules` の `"0"` を半角）を置いて確かめた。

1. **ローマ字表**: `data/preedit/romanji-hiragana.tsv` の3行目が `.` → `。`、4行目が `,` → `、`。打った点はいったん必ず「。」「、」になる。ここまでは普通の動き。
2. **Mozc の数字の変換**: `Composer::TransformCharactersForNumbers`（`composer/composer.cc`）が、入力中の表示・確定前の文字列・変換の鍵（`GetPreedit`、`GetStringForPreedit`、`GetQueryForConversion`、`GetQueryForPrediction`）に掛かり、直前が英数字の「。」「、」を「．」「，」にする。
   - 次の文字を見ない（コメントには「前も次も英数字」とあるが、コードは前だけ見る）ので、「合計は4.」も「4．」になる。
   - 幅は `character_form_rules` の `".,"`（既定は入力中の表示が全角）で決まり、数字（`"0"`）の幅とは別。数字を半角にしても点は全角のまま。手元で `4.1` を打つと、入力中の表示も、変換せずに Enter で確定した文字も「4．1」（数字は半角、点は全角）。`1,000` は「1，000」。Mozc 自身の試験（`PreeditFormAfterCharacterTransform`）が、この食い違いを期待値にしている。
   - 変換した後（`4.1`）は、候補の幅が別の規則で決まるので「4.1」になる。
3. **英単語を含む文だけ、本当に「。」になる**: `Converter::MarkEnglishSpans`（`apply_jaen_integration.py` が作る）は、英単語の見つかった文で日本語の部分をローマ字の打鍵から読み直し、その読みを鍵にする。この道は 2 の変換を通さないので、「。」「、」のまま変換にまわり、候補にも出る。
   - 手元の確かめ（直す前）: `pythonno3.9wotukau` → 「Pythonの3。9を使う」、`windowsno10.5` → 「Windowsの10。5」、`meetingwo4.1niokuru` → 「meetingを4。1に送る」。`1,000` は「1、000」。
   - 英単語が入らない `kyouha4.1desu` → 「今日は4.1です」は正しい。

「4.1」だけを打った場合に「4。1」になる道は、手元の確かめでは見つからなかった（手元の確かめでは「4．1」まで）。報告の文面に近い「4。1」が出るのは 3 の道。

## 決めたこと

数字のあとの点の扱い（`,` も同じ）:

| 打った並び | 結果 | 理由 |
|---|---|---|
| 数字 `.` 数字（4.1、3.14、1.2.3、192.168.0.1、v1.2、0.5%） | 小数点・版の点 | 数字の間の点は文の区切りではない |
| 数字 `.` 英字（3.x、2.x） | 点 | 版の番号の書き方 |
| 英字 `.` 数字（No.5） | 点 | 同上 |
| 数字 `,` 数字（1,000、1,000,000円） | 桁区切りのコンマ | |
| 数字 `.` で終わる、または日本語・閉じかっこが続く（合計は4.、4.では、「4.」） | **「。」** | 文や節が終わる点。下を参照 |
| 数字 `,` の後に日本語（りんご3,みかん2） | **「、」** | 同上 |
| 英字 `.` 数字以外（Python.、e.g.） | 従来どおり（`.,` の規則の幅） | この直しの対象外 |

**文末の「4.」を「。」にした理由**: 直す前は、実は「。」ではなく「4．」「4.」になっていた（上の 2）。つまり「今までどおり」ではなく変更になる。それでも「。」にしたのは、(1) 打つ人は文を終えるために点を押しているので「合計は4。」が自然、(2) 次に数字が来ない点を小数点にしても、日本語の文の中では読みにくい、(3) 数字の間の点は次の数字が来た時点で表示が「4.1」に直るので、打ちながらも困らない（「4。」の表示が「4.1」になる）。代わりに、番号つきの箇条書き「1.」のあとを「1。」にしたくないときは、F10（打った文字のまま）で「1.」にする。逆に文末も半角の点にしたいなら、`composer_decimal.inc` の `DecideNumberPunctuation` の `kKeep` を `kHalfWidth` / `kFullWidth` にする1行で戻せる（決めの本体はそこだけ）。

**全角・半角**: 点・コンマの幅は、となりの数字の幅に合わせる（半角の数字なら `.` `,`、全角なら `．` `，`）。`character_form_rules` の `".,"` の設定は、数字に挟まれた点・コンマでは見なくなる（Mozc 自身の試験 2 件の期待値を直した）。英字のあとの点は、これまでどおり `".,"` の設定。

## 打った算用数字が漢数字になる（2026-10-21、同じ枝で追加）

小数の直しのあと、打った算用数字が変換で漢数字になった（`980` → 九百八十、`10` → 十、`4.1` → `4.一`、`100` → 百、`1,2,3` → 一、二、三）。原因は点ではなく、数字の表記を選ぶ段にある。

1. **Mozc の数字の書き換え**: `rewriter/number_rewriter.cc` の `NumberRewriter::Finish`（この木では `patches/mozc-base.patch` 6772 行目付近で触っている）が、数字の読みの候補に漢数字・算用数字・全角の表記を足し、並べる。`converter/immutable_converter.cc` に足した `prediction::NumberDecoder`（同パッチ 2400 行目付近）も、同じ読みに漢数字と算用数字の候補を作る。打った `980` はどちらの候補にもなる。
2. **人工知能の全文の候補**: `tools/apply_jaen_integration.py` の `PreferWholePhrase`（1932 行目付近で呼び出し、`MatchWholePhrase` はパッチ 3226 行目付近）は、人工知能（Zenzai）の文を Mozc の文節の候補と突き合わせ、一致した候補を先頭へ移す。人工知能が「九百八十」と書いた文は、Mozc にも「九百八十」の候補があるため、そのまま先頭になる。
3. **選び手**: `tools/apply_selector_stage3.py` は変換の最後に文節の候補を移す（489〜500 行目付近）。そのため、その前の段で数字に戻しても、また漢数字が先頭になり得る。

直し方: `native/jaen-detector/typed_digits.inc` の `KeepsTypedDigits` / `ReplaceWithTypedDigits` を `Converter::PreferTypedDigits`（`tools/apply_jaen_integration.py` 220 行目付近）から呼ぶ。打った読み（文節の鍵）に算用数字がある文節だけを対象に、先頭の候補が打った数字をそのまま含んでいなければ、同じ数字を持つ候補を先頭へ移し、なければ先頭の候補の数字の部分だけを打った数字に戻す（`九百八十円` → `980円`、`十度` → `10度`、`4.一点` → `4.1点`、`10.0.0.一` → `10.0.0.1`）。数字の幅は打った鍵（数字の設定）に合わせる。かなで打った「一つ」「一番」「十分」は鍵に算用数字がないので触らない。呼ぶ場所は Mozc の書き換えのあと（`tools/apply_jaen_integration.py` 3219 行目付近）、人工知能と同音語の選択のあと（同 1656 行目付近）、選び手のあと（`tools/apply_selector_stage3.py` 506 行目）の3か所。

試験: 単体は `native/jaen-detector/typed_digits_test.cc`（組 `s` が g++ で組み立てて動かす）。`tests/conversion/decimal.tsv` に、かなで打った漢数字の語（一つ、一番、十分、三人、六時、百円、三匹、二十年、十一月、四十分、一人前、七十歳）を足し、算用数字に化けたら `tools/score_decimal.py` が違いとして数えるようにした。

### 見直しで直した3点（2026-10-21）

1. **数字のあとの漢字の単位を消していた**: 前の `KeepsTypedDigits` は鍵の数字と候補の数字を「トークン全体」で比べた。`3おく` の鍵のトークンは `3`、候補 `3億` のトークンは `3億`（億も漢数字なので同じトークン）で食い違うと判定し、`ReplaceWithTypedDigits` がトークン全体を `3` に置き換えて億を消していた（`10万です` → `10です`、`2千円` → `2円`、`3.5万` → `3.5`、`5百円` → `5円`）。
   直し: `KeepsTypedDigits` は、鍵の算用数字を含むトークンが候補にそのまま（前後が数字・点でない位置に）現れるかだけを見る。候補が足した漢数字（単位の億、かなから来た一）は比べない。`ReplaceWithTypedDigits` も、候補が漢数字だけで書いているとき、末尾の単位の前が鍵の数と同じ値なら単位を残す（`三億` → `3億`、`二千円` → `2千円`）。
2. **かなの漢数字が混ざると正しい候補を捨てていた**: `2にんいっしょ` の鍵のトークンは `2`、候補 `2人一緒` は `2` と `一`（一緒の一）の2つで、トークン数が違うとして `keep=false` になっていた（`10ねんいちど` / `10年一度` も同じ）。そのため `2人いっしょ` のような別候補が先頭へ上がったり、候補が漢数字だけだと数字が戻らなかった。
   直し: 1と同じく、鍵の数字が候補にあれば足りるとする。数字が無い候補しかないときは、鍵の数字が先頭（鍵が数字で始まる）なら候補の先頭の数トークン、末尾（鍵が数字で終わる）なら末尾の数トークンだけを置き換える（`二人一緒` → `2人一緒`、`一番二` → `一番2`）。
3. **`PreferTypedDigits` の宣言が private の所にあった**: `Converter` の `CompletePosIds` の直後（private）に足していた。`engine.cc` からの呼び出しがコンパイルできるよう、`RewriteAsyncCandidates`（public）の直後に移した。

小数点以下の `一・五`（`1.5` の候補）も、点と同じ間の記号として `1.5` に戻すようにした。

手元で確かめたこと（2026-10-21、Mozc なし）: 単体試験 `native/jaen-detector/typed_digits_test.cc` を `clang++ -std=c++20 -Wall -Wextra -Werror`（c++17 でも）で組み立てて 82/82（レビューの直しのあと。直す前は 58/58）。`PreferTypedDigits` と同じ手順（先頭が打った数字を含むか、含まなければ数字のある候補を先頭へ、無ければ数字の部分を戻す）を候補列に当てる小さな道具で、`3おく` / `3億`、`1まん` / `1万`、`10までです` / `10万です`、`2せんえん` / `2千円`、`5まんにん` / `5万人`、`3.5まん` / `3.5万`、`5ひゃくえん` / `5百円`、`2にんいっしょ` / `2人一緒`、`10ねんいちど` / `10年一度`、`三億` → `3億`、`二人一緒` → `2人一緒`、`一・五場合` → `1.5場合`、かなだけの `ひとつ` / `一つ`・`いちばん` / `一番`・`じゅうぶん` / `十分` が変わらないことを見た。`tools/score_decimal.py` は、単位を消した結果（`3円`）と、かなの `二人一緒` に化けた結果を違いとして数えることも確かめた。

確かめていないこと: 直した `apply_jaen_integration.py` を Mozc の木に当ててのコンパイル（`PreferTypedDigits` の宣言は public の `RewriteAsyncCandidates` の直後に置いたが、Mozc 本体は手元で組み立てられない）、組 `s` の実機の変換、人工知能（Zenzai）を通る道。

## レビューの指摘の直し（2026-10-21）
- `10%` / `10.5%` の鍵に候補 `10パーセント` / `十点五パーセント`: `%` と「パーセント」を二重に出していた。いまは `10パーセント` は「打った数字を含む」とみなして動かさず、`十点五パーセント` は `10.5%` に直す（パーセントの語は落とす）。
- `いち2` / `一2`、`にじゅう20` / `二十20`: 漢数字と数字が隣り合うと一つの塊になり、かなの漢数字が消えていた。いまは漢数字のすぐあとに数字が来た所で塊を分ける（`typed_digits.inc` の `NumberTokens`）。打った数字の直前の漢数字は、打った数字の判定の邪魔をしない（`MatchesAt`）。
- 鍵の終わりの「,」「.」（`1,`、`100.`）は句読点で、数字の一部にしない。`1,2` に `一、二` が来たら `1,2` に直す（読点を挟んだ数字は鍵の「,」の数字）。
- 試験: 単体試験に24件足し、`decimal.tsv` に「かなの数 + 打った数字」の5文（いち2、にじゅう20、はちじゅう80、さん10、ご7）を足した。`tools/score_decimal.py` は、打った数字のすぐ前の漢数字が消えた結果も違いとして数える。
- 確かめていない: `g++` はこの環境になく、`clang++` で確かめた。Mozc の木が無く、`apply_*.py` の当たり数と、新しい C++ の本物の組み立ては未確認。
