# 判定の門を IME の変換に組み込む（2026-10-21、枝 `feat/jev-gate-ime`）

目的は速さ（全文の人工知能の生成を減らすこと）。判定の門（`docs/jev-gate.md`）を空白キーの変換の流れに入れ、
「要らない」と当てた変換は生成を飛ばして、生成なしの候補から選ぶ。**既定は無効で、今の動きは変わらない。**
正解を増やす頭（v4sel の選ぶ頭）は使わない。

## 組み込み方

`tools/apply_jev_gate.py`（`apply_latency_profile.py` の後に最後に動かす。Linux の試験用。Windows の組み立てには入れていない）。

- 門の場所: `engine/engine.cc` の `PreferWholePhrase`。ここが全文の生成（AzooKey の `all_zenzai`。先回りの結果の受け取りも含む）の問い合わせで、
  その直前に `JevGateSkipGeneration`（`tools/jev-gate/engine_gate.inc`）を呼ぶ。英単語をはさむ区間の問い合わせ（`PreferWholePhraseRuns`）は門を通さず今まで通り生成する。
- 候補の作り方は学習のときと同じ（`tools/jev_gate_build.py` の `make_candidates`）: n = Mozc の第一候補をつないだ文、
  w = AzooKey の辞書の文全体（人工知能なし。新しい書き出し `ConvertTextNoAI`）、c = Mozc の文節ごとの上位16を費用の和の小さい順に並べた組（最大32）。
  この順に表記が同じものを1つにし、先頭の k=4 個（と前の文の終わり24字、読み）を模型に渡す。
- 推論: `tools/jev-gate/jevgate_core.h`（C++ だけ、AVX2）。OpenMP の代わりに自前のスレッドの組（`JEVGATE_THREAD_POOL`）を使い、Bazel の組み立てに部品を足さない。
  `jev_gate.cc` が文字の番号付けと入力の並びを作る（`jevgate.py` の featurize と collate と同じ。torch の出力との差は最大 1e-6、半精度の重みで 1.3e-4。`tools/jev-gate/jev_gate_cases.py` と `jev_gate_check.cc` で確かめられる）。
  実行時に AVX2 と FMA がなければ模型を読まず、門は無効のままになる。
- 門が「要らない」と当てたとき（`need_k` がしきい値未満）: 上位の候補を選んで生成を飛ばす。選び方は
  zenz（既定。`ScoreZenzaiSuffixes`＝既にある一括採点で上位の候補を採点して最大）か、student（模型自身の点。採点なし）。
  選んだ候補は `PreferWholePhrase` と同じ確かめ（`MatchWholePhrase`、`private_surface::Find`、固有名をかなにしない決まり）で文節ごとの候補の番号にする。
  実現できなければ次点、どれもだめなら今まで通り生成する。採点や推論が失敗したときも今まで通り生成する。
- 門が有効なときは、打っている間の先回りの生成（`prefetch_typing_`）を止める（要らない生成を走らせないため）。
- 人工知能なしの辞書の変換では、打ち間違いの補正の探索を止める（変換1回で約55ミリ秒かかり、止めないと門の費用が倍になる。`MYIME_JEV_GATE_NOAI_TYPO=1` で戻せる）。

### 切り替え（環境変数）

| 名前 | 意味 |
|---|---|
| `MYIME_JEV_GATE=<しきい値>` | `need_k` がこの値以上なら今まで通り生成する。未設定、0、空なら無効（既定） |
| `MYIME_JEV_GATE_MODEL=<jevgate.bin>` | 重みの表（隣に `<表>.vocab.json`）。読めなければ無効 |
| `MYIME_JEV_GATE_SELECT=zenz\|student` | 生成を省くときの選び方（既定 zenz） |
| `MYIME_JEV_GATE_SCORE_N=<数>` | zenz で採点する候補の数（既定は k=4） |
| `MYIME_JEV_GATE_THREADS=<数>` | 模型のスレッド数（既定4、計算機の数が少なければそれ） |
| `MYIME_JEV_GATE_LOG=<ファイル>` | 門の判断を1行ずつ書く（無効のときも、生成が走った変換を `generate_nogate` として書く） |

## 模型

v3m（ドライブ）は手元になかったので、**代用の模型**を手元で学習した（`ContextIME/release/jevgate-proxy/`）。
d=256・4層（v3m と同じ形、489万）、ウィキペディア9万文（`records-01` の先頭）、3周、CPU で約3時間。確かめ用の `need_k` の AUC は **0.743**（v3m は 0.809）。
確かめ用での生成の割合としきい値: 0.15 で 74%、0.2 で 63%、0.25 で 54%（v3m は 0.2 で 61%）。
**下の表の正解数は代用の模型のもの。v3m では門の質が上がるので、正解の損は小さくなる見込みだが、値は未測定。** 時間の費用（門の推論）は同じ形なので v3m でも同じ。
置き場: 下書きの配布ページ `model-jevgate-proxy`（公開しない）。CI は `gh release download` で取る。

### 値付け（speed-claims）

- 門なしで、全文の生成（all_zenzai）が変換1回の時間に占める割合は **59.3%**（884変換×3回、入り口の全体に対する allz の合計）。生成を全部なくせても速さは最大 **2.45倍**（Amdahl）。
  生成が走るのは変換の約 95%（残りは1文節で、そもそも生成しない）。
- 生成を省くのは門に来た変換の 20〜40%（しきい値による）。1回あたり生成は平均 約200ミリ秒（allz の平均）。
- **zenz で候補を採点して選ぶ形は、速くならない。** 採点（上位4個）の平均 189ミリ秒は、省く生成の平均（約200）とほぼ同じで、
  さらに全部の変換に門の費用（辞書の変換と推論）約 31ミリ秒が上乗せされる。中央値は +25〜28%（遅い）。上位2個だけにしても +12%。
- 速くなったのは、**採点をしない student 選び**（模型自身の点）だけ。中央値 -3.6%、平均 -2.7%、省く変換は 31ミリ秒で済むが、正解は 258 減る（-5.3%）。
  90%点はどの設定でも門なしより悪い（+5〜7%）。90%点は生成が走る変換で決まり、そこへ門の費用 約42ミリ秒が乗るため。
- 机上の見込み（生成 61%、正解 4,866）との違い: 見込みには採点の時間も、辞書の変換と推論の費用も入っていなかった。実測では、生成 66〜71% で、
  代用の模型の正解は -64（0.2、zenz）。v3m の門の質（AUC 0.809）なら損は小さくなるはずだが、zenz 採点の時間が省く生成の時間と同じである点は模型によらない。

## 実現できなかった候補・注意

- 最大の点の候補を文節ごとの候補の番号にできなかったのは、省いた変換の約 4%（0.2、zenz で 33/768）。次点で代える（なければ生成）。
- 選ばれた候補の出どころ（0.2、zenz、正解を数えた組の合計 1,904 回）: n・w・c のすべてに入る文 72%、w と c に入る文（第一候補とは違う）21%、n と c 5%、w だけ・c だけ 約1%。
- 門に来る変換は、複数の文節に分かれ、すべて自由な文節の変換だけ。1文節の文と英単語まじりの区間（`PreferWholePhraseRuns`）は元から対象外（対象にすると候補の作り方が学習と合わなくなる）。
- 先回り（打っている間の生成）は止める。この試験は先回りなし・上限なしの条件で、利用者の PC の既定（先回り 120ミリ秒、上限 1000ミリ秒）での時間は測っていない。
  先回りが効く打ち方では、生成の多くが打っている間に終わっているため、門で省ける空白キーの時間はこの試験より小さい（見込み、未測定）。
- 辞書の文全体の候補 w は、打ち間違いの補正を止めた辞書の変換から作る（学習のときの w は補正を含んでいたかもしれない）。typo150 は -2〜-4。

## 試験の流し方

```
gh workflow run linux-test.yml -R J-KAMMA/compound-ime --ref feat/jev-gate-ime \
  -f jev_gate_configs='["off","0.15","0.2","0.25","0.2_student","0.2_zenz2"]' \
  -f jev_model_release=<下書きの配布ページ> -f jev_model_file=jevgate-fp16.bin -f jev_gate_reps=3
```

- 組: ka、c、e1、e2、g、h、kd、ke（正解を数える。設定ごと）と、時間の kp（別の仕事 `jev-gate-timing`。設定を入れ替えて繰り返す）。同時に流す数は 15 + 1（max-parallel 15）。
- 設定の名前: `off`（門なし）、`<しきい値>`（zenz 採点）、`<しきい値>_student`、`<しきい値>_zenz<数>`。
- まとめ（`jev-gate-report` の成果物 `report.md`）は `tools/jev_gate_report.py`。門なしの出力が同じかは、`jev_gate_apply=false` で流して `--same` で比べる。
- v3m で流すには、`jevgate-fp16.bin` と `jevgate-fp16.bin.vocab.json` を下書きの配布ページに置いてその目印を渡す。
